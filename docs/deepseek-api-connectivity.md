# DeepSeek API key: модельный API и связь с агентом

## Вывод

**Один API key DeepSeek Platform не связывает Telegram-бот на VPS с агентом на ПК.** Ключ авторизует запросы к облачным моделям DeepSeek. Для передачи Telegram-сообщения локальному агенту нужен отдельный сетевой relay/connector между VPS и ПК.

## Что подтверждает официальная документация

- DeepSeek Platform принимает HTTP-запросы с Bearer API key к облачному endpoint `https://api.deepseek.com`.
- Chat Completions получает список сообщений и возвращает ответ модели; при включённом `stream` отдаёт поток частей ответа.
- Tool/function calling возвращает модели запрошенные вызовы. Клиентское приложение должно выполнить соответствующую функцию и передать её результат обратно модели; модель сама не запускает функцию и не может читать файлы ПК без такого клиентского кода.

## Сопоставление вариантов

### Оставить агента на ПК — выбранный вариант

1. Telegram-бот на VPS получает сообщение, создаёт `correlation_id` и отправляет «Размышление».
2. PC connector сам подключается к VPS по защищённому исходящему каналу и получает запрос.
3. Connector передаёт его установленному агенту, у которого доступны память, файлы и Google Calendar на ПК.
4. Агент возвращает результат через connector; relay редактирует исходное Telegram-сообщение.
5. Если OpenCode использует DeepSeek Platform, API key настраивается в профиле OpenCode на ПК и используется только для вызовов облачной модели. Официальная инструкция OpenCode подключает DeepSeek через `/connect`; ключ хранится в профиле OpenCode. Инструменты и память исполняются локальной средой.

### Вызывать DeepSeek API прямо из Telegram-бота на VPS

Это технически возможно по API key, но **не связывает бота с текущим ПК-агентом**. VPS-бот будет напрямую вызывать облачную модель. Чтобы при таком варианте использовать календарь, задачи и локальные файлы, придётся отдельным способом предоставить модели инструменты/данные, а весь нужный контекст передавать на сервер. Это другая архитектура и не соответствует текущему решению о локальном агенте как источнике памяти.

## Связь с `Bot_lanch_tz`

В `bot_lanch_tz/vlm_parser.py` бот делает исходящий HTTP-запрос к настроенному OpenAI-совместимому endpoint, добавляет Bearer API key при наличии и использует timeout. Этот паттерн подходит для вызова облачной модели из процесса бота. Он не создаёт соединение к локальному агенту и не открывает серверный доступ к ПК.

## Ключи и данные

- Telegram bot token хранить на VPS.
- API key DeepSeek хранить только в том процессе, который реально вызывает DeepSeek Platform — это может быть агент на ПК или VPS-бот при выборе альтернативной архитектуры.
- Google OAuth credentials и токены календаря хранить на ПК агента, если выбранный процесс взаимодействия с календарём выполняется там.
- Запросы к Platform отправляют текст облачной модели. Перед передачей HR-контекста и персональных данных кандидатов учитывать, что inference по API происходит на стороне сервиса DeepSeek, даже когда вызывающий агент запущен локально.
