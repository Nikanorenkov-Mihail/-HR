# Инструкция агенту проекта

## Контекст

Это Telegram-транспорт на VPS для одного HR-специалиста и DeepSeek-агента на постоянно включённом ПК. Бизнес-логика, задачи, долговременная память, Google Calendar и расписание напоминаний принадлежат агенту. Бот не выполняет эти действия сам.

Перед работой прочитай `README.md`, код и относящиеся к задаче документы в `docs/`. Проект содержит первый транспортный каркас; сохраняй выбранный Python/aiogram/aiohttp и схему VPS relay + PC connector, если пользователь не попросил об изменении. Фиксируй новые архитектурные решения в соответствующих документах.

Референс Telegram-развёртывания — локальный проект `Bot_lanch_tz`, указанный в контексте разработки. Используй только как пример long polling, allowlist Telegram ID, Docker Compose и постоянного хранилища. Не читай и не копируй `.env`, реальные токены, базу данных и предметную логику того бота. Его VLM HTTP API не является интерфейсом локального DeepSeek-агента, пока это отдельно не подтверждено.

## Архитектурные границы

- Следуй `docs/architecture.md` и `docs/deepseek-agent-instructions.md`.
- Интеграцию с OpenCode реализуй по `docs/opencode-integration.md`: headless `opencode serve` только на localhost ПК + отдельный connector, который забирает задания с VPS.
- VPS-бот — тонкий Telegram relay: проверяет единственный разрешённый Telegram ID, отправляет «Размышление», пересылает запрос агенту, редактирует исходное сообщение ответом и доставляет агентские напоминания. Не разбирай пользовательский текст на задачи/события и не принимай за агента решений.
- Бот не хранит бизнес-задачи, календарные события или правила напоминаний. Допустимо хранить только минимальное техническое состояние доставки/очереди (correlation ID, message ID, статус, retry), с коротким сроком хранения.
- DeepSeek-агент на ПК — источник истины для задач, памяти и напоминаний; он же читает/создаёт события Google Calendar в соответствии с `docs/deepseek-agent-instructions.md`.
- Для OpenCode используй его локальный HTTP API с фиксированным портом и Basic Auth; не публикуй API OpenCode в Интернет и не проксируй произвольные OpenCode endpoints в Telegram. Connector на ПК сам опрашивает VPS по аутентифицированному HTTPS.
- OpenCode часто обновляется: не полагайся только на зафиксированный номер версии или старые примеры API. При изменениях сверяй актуальную официальную документацию. Connector должен проверять `/global/health`, актуальную спецификацию `/doc` и доступность `hr-assistant`; несовместимая версия должна останавливать выдачу заданий с понятным состоянием.
- API-ключ DeepSeek Platform авторизует запросы к облачной модели, но не создаёт сетевой канал и не даёт VPS доступ к агенту/файлам на ПК. См. `docs/deepseek-api-connectivity.md`.
- Если агент недоступен или обработка завершилась ошибкой, отобрази понятное сообщение и не сообщай об успешной записи/операции.
- Для календарного конфликта агент предупреждает пользователя и ждёт выбора: создать несмотря на пересечение или изменить запрос. Создавать конфликтующее событие до выбора нельзя.
- Доступ к боту ограничь настроенным Telegram user/chat ID до передачи любых данных агенту. Архитектура должна позволять позднее добавить сотрудников с отдельными контекстами и правами.
- Не выполняй реальные внешние действия при разработке/документировании. Токены Telegram и Google OAuth хранятся в своих средах; Google OAuth-токены должны оставаться на ПК агента, не на VPS.

## Данные и приватность

- Не добавляй секреты в репозиторий. Используй переменные окружения или защищённое хранилище и предоставляй только имена переменных в примерах конфигурации.
- Не копируй содержимое `Ассистент/assistant_tasks.json` в этот проект: там есть данные рабочих задач и клиентов. Используй только общую модель задач из проекта «Ассистент» как ориентир.
- Своди логи к техническим событиям и идентификаторам корреляции; не записывай токены, переписки HR и персональные данные кандидатов без установленной необходимости.
- Google Calendar разрешён агенту для чтения и создания событий. Не предоставляй агенту инструменты обновления/удаления событий; не включай в бота календарные полномочия.

## Рабочий процесс

- Сохраняй выбранные в проекте язык, библиотеки и соглашения после их появления; не вводи лишние зависимости.
- Изменяй проект небольшими законченными шагами и актуализируй документы при изменении архитектурных решений.
- Не утверждай, что локальный агент, Telegram или Google Calendar интегрированы, если соединение не было фактически настроено и проверено.
